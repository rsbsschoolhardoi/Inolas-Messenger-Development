# 🌐 Inolas Messenger (Core Production Development)

> **Sovereign, Resource-Optimized, and Post-Email Communication Infrastructure.** Built entirely from first principles on a minimal budget, replacing traditional centralized dependencies with self-sovereign cryptographic identities and peer-to-peer mesh networking.

---

## 🚀 Key Capabilities & Architectural Highlights

### 🔒 1. Self-Sovereign Identity Protocol (Zenoa ID)
* **Zero-Email Sign-Up:** Completely eliminates traditional SMTP and third-party identity management (like 'Sign in with Google'). Users claim their cryptographic passport directly under `@zenoa` or specialized internal custom roots (`username@custom_root`).
* **RAM-Isolated Sandboxing:** Encryption and decryption keys exist exclusively inside the highly volatile system memory (RAM). Message payloads are never written as plaintext to the hard disk storage.
* **0ms Server Purge Engine:** Sub-second transactional delivery network that flushes messages from the server queue instantly upon client acknowledgement, maintaining a true zero-retention cloud footprint.

### 📡 2. Off-Grid Resilient Communication (Nearways Skypie)
* **Zero-Internet P2P Highway:** Leverages local area network (LAN) subnets and socket broadcasting. If routers lose broadband connection but retain electrical power, the node dynamically maps active peers across large areas.
* **100 MB/s Raw Gigabit LAN Throughput:** Peer-to-peer file transfers and heavy-duty 4K multimedia bypass remote cloud limits, routing data directly between device sandboxes.

### 🎨 3. Context-Aware Dynamic UI & Multi-Runtime Performance
* **Dynamic Bubble Scaling:** Real-time variable matching that calculates HEX/RGBA background contrast to adjust font weight, styling, and bubble roundness on the fly without system reboots or layout lags.
* **Modern App Pipeline:** Formulated with 99.3% strict **TypeScript** for strict type-safety, built atop **Bun** runtime for sub-millisecond execution, and enclosed within lightweight **Docker** containers.
